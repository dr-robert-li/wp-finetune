## API
- `judge_units(units, base_url, model, workers=4, on_result=None, max_tokens=2048)`:
  - Builds one client: `OpenAI(base_url, api_key="none", timeout=600, max_retries=0)`.
  - Runs `ThreadPoolExecutor` with `submit` + `as_completed`.
  - Calls `on_result(judgment)` in the calling thread as each unit finishes.
  - Returns the judgments sorted by `id`.
- `judge_one(client, model, unit, max_tokens)`:
  - Makes 2 attempts at most.
  - Retries on an exception or an unusable output.
  - If both attempts fail, returns `status: "unjudged"`, `attempts: 2` and `error`. `error` is `"parse_failure"` or `"<ExcType>: msg"`, taken from the last attempt.
- `to_judgment(unit, raw, attempts)` turns raw text into a judged Judgment, or `None`. The tests call it directly.
- `_judge_create` is copied from `eval/eval_judge.py:47-76`, including the fallback that drops the kwarg if the template rejects it. Two changes: the default `max_tokens` is 2048, and the warning text is shorter.
- `parse_judge_response` is copied verbatim from `eval/eval_judge.py:310-383`. A `diff` of the source lines against the copy is empty.

## Decisions
- **Prompt:** exactly `"<wp_judge> Evaluate this WordPress code:\n\n```php\n{code}\n```"`. One user message, no system prompt. `temperature=0` and `extra_body.chat_template_kwargs.enable_thinking=False`.
- **"Usable" output:** the parse returns a dict with a numeric (non-bool) `overall_score`. Anything else counts as `parse_failure`, so the unit is retried. There is no fallback that derives the overall score from the dimensions (the research found that all captures emit it).
- **`scores`:**
  - Taken only from the parsed JSON (A5), with native key names.
  - Keeps keys whose value is integer-valued (an int, or a float like `7.0`, cast to int).
  - Drops `verdict`, `overall_score`, bools and non-integers.
- **`overall_score`:** `int(round(x))`.
- **`verdict`:** passed through as the model gave it (`j.get("verdict")`).
- **`critique`:** the text before the first `[/REASONING]`, stripped. If that marker is missing, it is the text before `<judge_output>`, so the JSON block never leaks into the critique. This is a small superset of the contract.
- **No overflow-halving.** `DIM`, `TOPICS` and `rank` are not defined here.

## Deviations
- There is one judge-side deviation. `parse_judge_response`'s fallback strategies 1-4 can pull JSON from outside `<judge_output>` (raw, fenced, or the first `{…}`). I kept it verbatim, as the task instructs.
  - It is still JSON, never prose, so A5 holds in spirit.
  - On real captures every success comes through the `<judge_output>` path.
  - Flag: if A5 is meant to be strictly tag-only, those strategies would need trimming, which would break the verbatim copy.
- No shared-file changes are needed. The `max_tokens` and `workers` defaults match `Config`.
