## scan(path, on_result=None, **cfg)
- `cfg = config.load(**cfg)`, with None values ignored, so the CLI passes its flags straight through.
- The target is extracted into a `tempfile.TemporaryDirectory` (change 12) by `extract.load_target(path, tmp, cfg)`.
- `collect_units(root, cfg)` returns a 3-tuple. I confirmed this against `build_notes/W1.md` and the real `extract.py`.
- `judge_units(units, cfg.base_url, cfg.model_file, cfg.workers, on_result=cb, max_tokens=cfg.max_tokens)`.
- **Model name choice:** `cfg.model_file` is sent as the OpenAI `model`. llama-server ignores it, and it keeps logs readable.
- `model_meta = {"file": cfg.model_file, "base_url": cfg.base_url}` (change 7).
- `build_report(..., files_scanned=files_scanned)`. W3 accepts the kwarg, so `target_meta` is not mutated.
- **Callback contract:** `on_result(judgment, done, total)`.
  - It fires once as `(None, 0, total)` right after extraction. The CLI uses this for its ETA line and the API for `progress.total`.
  - After that it fires once per judgment.
  - W2 calls its own `on_result` from the calling thread, so no lock is needed.
  - This contract differs from W2's single-argument `on_result(j)`. scan wraps W2's callback and adds the counter.

## CLI
- `wpjudge scan <path> [-o report.json] [--workers N] [--base-url URL] [--model-file F]` (change 16).
  - With no `-o`, the report goes to stdout.
  - stderr gets `"<n> units, ETA ~<n/11> min"` (change 14).
  - Exit code is 0 even when every unit is unjudged (change 8). I checked this against a dead port: valid report, `overall_score` null, `low_coverage` true.
- `wpjudge serve [--host 127.0.0.1] [--port 8000]` runs `uvicorn.run("wpjudge.api:app", workers=1)`.
  - Docker needs `--host 0.0.0.0` (W5).
  - I smoke-tested it on :8799: GET of an unknown id returned 404, and shutdown was clean.

## API (r3 design B, endpoints and restart behaviour as r3)
- Endpoints: `POST /jobs` returns 202 `{job_id}`. `GET /jobs/{id}` returns `{id,status,progress,error,report?}`. `GET /jobs/{id}/functions` returns `{functions:[...]}`.
- Bearer auth uses `hmac.compare_digest` against `cfg.api_key`, which is read at request time. It applies to all three endpoints, including `/functions`. Auth is off when the key is empty.
- The size middleware runs on POST and decides on the header alone:
  - no Content-Length: 411
  - non-numeric or negative Content-Length: 400 (change 12)
  - Content-Length over `cfg.max_upload_mb`: 413
  - The streamed save re-checks the size as a second line of defence.
- Upload type: a suffix other than .zip/.tar.gz/.tgz (case-insensitive) gets 415.
- `webhook_url` must have the http or https scheme and a host, otherwise 400. The check runs before the job dir is created. Delivery is a POST via stdlib `urllib.request` with a 5 s timeout and one retry, and it never raises.
- Job ids must match `re.fullmatch(r"[0-9a-f]{32}")` before any path is built, otherwise 404. Ids are `uuid4().hex`.
- Disk store per job: `jobs_dir/<id>/{job.json (atomic tmp+replace), functions.jsonl, report.json, upload.*}`.
  - The upload is deleted after the scan.
  - `functions.jsonl` rows drop `code` and `raw` (matching the report's `functions[]` rows, change 4). Without this, partial results would carry full source and raw model output.
- Restart behaviour:
  - Jobs in `running` are marked `failed` with "interrupted by server restart; resubmit".
  - Jobs in `queued` are re-enqueued in mtime order.
  - `done` and `failed` jobs are served unchanged.
- The queue is created in lifespan, and the worker gets it as an argument. A `None` sentinel at shutdown stops the worker. This lets TestClient restart the app cleanly within one process.
- Retention: `sweep()` runs at startup, after every job, and hourly when idle. It deletes dirs whose mtime is older than `cfg.retention_days`. **Deviation from r3:** it only touches dirs whose names are job ids, so a misconfigured `jobs_dir` cannot lose unrelated dirs.
- A failed scan sets status `failed` with error `"<ExcType>: <msg>"`, for example an `extract.Rejected` archive. No webhook is sent for failed jobs.

## Deviations and notes
- The upload is saved as `upload.zip` or `upload.tar.gz`. An archive without a single top-level dir therefore gets the report `target.name` "upload". W1 names it from the archive name. The original name is kept in `job.json` (`upload_name`), but it is not injected into the report. Add that if it matters.
- On `ValueError` (`extract.Rejected`: missing path, not an archive, unsafe archive), the CLI prints `wpjudge: <msg>` and exits 2 instead of printing a traceback. Unjudged units still exit 0.
- Extraction for API jobs uses the system temp dir (scan's TemporaryDirectory), not the job dir. The zip-bomb and ratio guards run in `load_target` either way.
- The known r3 ceilings still apply:
  - The queue is in memory, so the app must run as one process.
  - The webhook is unsigned and runs on the worker thread.
  - A crash outside `run_job`'s try leaves a job `running` until the next restart. This is marked with a `ponytail:` comment.
  - There is no cancel and no job listing.
- A stale worker from a previous TestClient app can still be draining its old queue while the module `CFG` is swapped. Tests wait for their jobs to finish before teardown. This cannot happen in production, where there is one app per process.

## Check
`cd harness && .venv/bin/python -m pytest tests/test_api.py -q`. It ran 10 passed in about 1 s, and the full `tests/` run was 30 passed. It has not been validated yet; validation is for the evaluator.

The tests drive the real app via `TestClient`, with `api.scan` monkeypatched to a gated stub and `api.CFG` swapped per test. They cover:
- auth on and off, including `/functions`
- 413, 411, 400 and 415, plus no job dir left behind
- bad ids: `/jobs/..%2f..`, `/jobs/..%2f../functions`, uppercase, unknown
- webhook scheme rejection (file, ftp, gopher, missing host, javascript)
- webhook delivery to a stdlib http.server
- queue order: three jobs, one at a time, FIFO
- partial results mid-run (`progress {1,3}`, one function, no report)
- a failed scan
- restart: running becomes failed, queued jobs run in mtime order
- retention: 8 days deleted, 6 days kept, a non-job dir untouched

No model server was run.
