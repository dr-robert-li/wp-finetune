## tests/e2e.sh
Usage: `tests/e2e.sh <section>... | all`. The `all` order is malicious, serverdown, cli, library, real, parity, api, allinone. The script prints PASS/FAIL lines plus a total, and exits non-zero on any FAIL. The log goes to `$WORK/e2e.log`.

Sections:
- **cli**
  - dir, .zip and .tar.gz at `--workers 1`, plus one dir run at `--workers 4`.
  - Each report gets: schema v1 keys and the row shape from change 4 (no code/raw); units and skip rows equal to expected.json; exact skip counts; coverage ≥ 90; and a full **independent recompute** of the summary from `functions[]`: coverage, the LOC-weighted overall, the cap invariant with exactly those `cap_reasons`, verdict_counts, dimensions, and worst_functions.
  - Across the three scans: files_scanned agrees; sha256 is set for archives and empty for the dir; overall |Δ| ≤ 6 between dir and the archives.
  - The workers=4 run checks verdicts only (units and skips are already checked).
  - SQLi capping is asserted only because the pre-run showed it.
  - Planted < clean is checked with a +6 tolerance.
  - anti_patterns must include security or sql_safety.
  - Also checks the stderr unit-count/ETA line, that `model.file` equals `--model-file`, and that the report goes to stdout without `-o`.
- **malicious**
  - 12 archives: zip-slip, absolute path, zip symlink, 300 MB bomb, a 15 MB 1000× ratio bomb, oversize (`WPJUDGE_MAX_TOTAL_MB=1`), too many files (`WPJUDGE_MAX_FILES=10`), tar slip, tar symlink, tar hardlink, and a non-archive .zip and .tar.gz.
  - Each must exit 2 with no traceback and no report written. TMPDIR must be empty afterwards, no `wpjudge_e2e_escape*` file may exist under WORK or /tmp, and the symlink target must stay untouched.
  - Sanity check: the benign zip is still accepted.
- **serverdown**: dead port. Expects exit 0, all 10 units unjudged with an error and 2 attempts, overall null, low_coverage true, a valid schema, and a recompute that passes.
- **library**: `from wpjudge import scan` on the dir and the zip, workers=1. Same fixture checks.
- **real** (changes 14 and 15)
  - Downloads the classic-editor and twentytwentyfour zips from downloads.wordpress.org into `$WORK/real` and scans each at the default number of workers.
  - Checks schema, coverage ≥ 90, the recompute and target.type, and records wall time.
  - It only WARNs if the unit count differs from 39 or 60.
  - Prints the template vs function score split.
- **parity** (change 13)
  - Stops the host server, then runs a driver-580 `--version` smoke of `server-cuda13-b11515`.
  - The container serves the same GGUF (read-only bind mount, `--parallel 1`). It gets r2's 16 prompts (the first 16 `<wp_judge>` rows of `data/reasoning_dataset/openai_val.jsonl`), sequentially, and then the host server gets the same 16.
  - Pass condition: 16/16 verdicts equal and overall |Δ| ≤ 6.
- **api**
  - Starts `docker compose` under project `wpjudge-e2e` with an override in `$WORK/compose.e2e.yml`. The override bind-mounts the host GGUF dir read-only at `/models` (so there is no 16.6 GB download), sets `WPJUDGE_MODEL_FILE` and `WPJUDGE_API_KEY`, and remaps the port with `ports: !override`.
  - Job flow and listener: submit, then partial `/functions` while running (SKIPped if not observed), then done, then the report gets the fixture checks, then `/functions` has 10 rows. The webhook goes to a stdlib listener started *inside* the harness container, so no host networking assumption is made. The listener must receive the report.
  - Input checks: 415 for .py; 413 for 60 MB; 400 for a file:// webhook; 400 for a non-numeric Content-Length. `/jobs/..%2f../functions` and `..%2f..%2fetc%2fpasswd` must return a 4xx (not 200/500). A zip-slip job must end `failed`, with nothing escaped in the container.
  - Auth on, after recreating the harness with a key: 401 for no key or the wrong key on GET `/jobs/{id}`, on `/functions` and on POST; 200 with the right key. The done job survives the restart.
  - Restarting while a job runs gives `failed` with "interrupted".
  - Retention: the job dir touched to 8 days ago is swept (404); the one at 6 days is kept (200).
  - Ends with `down -v`.
- **allinone**: builds `--target allinone`, runs it with `--gpus all`, the GGUF mounted read-only and port 8001, scans the fixture zip through the API, and applies the fixture checks.
- **prerun**: regenerates the pre-run into `$WORK`. It does not overwrite the committed copy.

Host server handling:
- `host_up` reuses whatever answers on `$PORT`. Otherwise it starts the host server with `--parallel $HOST_PARALLEL` (default 4, needed for the workers=4 run) and `-c 4×8192`, and logs nvidia-smi.
- `host_down` (before the docker sections, and at exit) kills only a server the script started.
- `trap` cleans up the compose stack and containers.
- Docker is called directly if `docker info` works, else via `sg docker -c`.

## Deviations, notes, open questions
- The golden SQLi cap asserts "≥ 1 pre-run-capped SQLi unit in cap_reasons" rather than both, because of the threshold-4 fragility described above.
- I did not add a separate malicious-builder script. The archives are built by `chk.py make-malicious` inside e2e.sh.
- The pre-run used a `--parallel 1` server, while the cli golden runs workers=1 against a `--parallel 4` server (one sequence at a time; r2 measured sequential as deterministic). Set `HOST_PARALLEL=1` to match the pre-run exactly; the workers=4 run then still passes, it just runs serialized.
- The api section relies on compose merging the llama `/models` volume by target path, and on `ports: !override` (compose ≥ 2.24; the host has v5.2).
- The fixture is scanned in place under `harness/tests/fixtures/...`. A W1 path rule that matched absolute path segments (`tests`) would skip everything. W1 uses relative paths today; the dir golden would catch a regression.
- The API report's `target.name` comes from the extracted top-level dir (`vuln-plugin`). W4 noted that archives without one get "upload". Not asserted.
