### Parity (host vs container, 16 val prompts)
- **Run 1 FAILED**: verdicts 15/16. `|d|` "max 8 <= 8" also failed because only 15 deltas existed (the check needs len 16).
  - Host prompt index 13 returned no parseable `<judge_output>`.
  - Root cause, probed on a host `--parallel 1` server with all 16 prompts in sequence:
    - With the default `cache_prompt` (true), prompt 13 reuses the previous prompt's slot KV. It degenerates into a repetition loop (`...No IOPerf score 8/10 —` repeated, `finish_reason=length`).
    - With `cache_prompt: false`, it ends normally: PASS, 66.
    - Sent alone on a fresh server, it is also 66.
  - The parity probe `_send` in `tests/e2e.sh` (chk.py) never got the a8c457f `cache_prompt: false` change that `judge.py` got. v1 hid this because the host ran `--parallel 4`, and the v1 diagnostic `parity_host_p1.json` already showed this null. WS-D's `HOST_PARALLEL=1` default now hits it on every run. This is breakage introduced by the merge.
  - Fix: add `"cache_prompt": False` to `_send` (see Edits).
- **Re-run PASSED**: verdicts 16/16, **max |Δ| 8 (prompt 10: host 82 vs container 74, same as v1), mean |Δ| 1.50**. |Δ| ≤ 8 holds.
